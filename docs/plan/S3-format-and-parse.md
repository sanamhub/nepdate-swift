Read first: `shared/spec/FORMATTING.md`, `shared/spec/PARSING.md`, `docs/API.md` (formatting,

## Tasks

### S3-01 Names and digits
`Month.name(_:)`, `Month.shortName(_:)`, `Weekday.name(_:)`, `Weekday.shortName(_:)` from `switch`
statements returning string literals (FORMATTING §1, exact strings; ADR-0002 §4: no `[String]`
table, which would be built on first access). `nepaliDigits(_:minWidth:)`: digit `d`
is `Unicode.Scalar(0x0966 + d)`; a negative `n` gets a leading ASCII `-`; `minWidth` pads with `०`
and counts digits, not bytes. No `NumberFormatter`, no `String(format:)`.
- AC1: `Month.ashad.shortName() == "Asa"`, `Month.ashoj.shortName() == "Aso"`,
  `Month.shrawan.shortName(.nepali) == "साउन"`.
- AC2: `nepaliDigits(2081) == "२०८१"`, `nepaliDigits(5, minWidth: 2) == "०५"`.

### S3-02 `description`, `short`, `long`
FORMATTING §2–4, and the `appendShort(to:)` and `appendLong(to:)` forms (ADR-0002 §4). The
`String`-returning form is `var out = ""; out.reserveCapacity(n); appendX(to: &out); return out`,
where `n` is the exact UTF-8 byte count of the result (a Devanagari digit or letter is 3 bytes).
Append from literals and digit bytes; no string interpolation, no `Character` iteration.
- AC: golden `dates.tsv` columns `to_string` (`description`), `unicode`
  (`short(lang: .nepali)`), `long_en`, `long_en_weekday` (`long(weekday: true)`), `long_ne`,
  `long_ne_weekday`, `dmy_dash_nopad` (`short(order: .dmy, separator: .dash, pad: false)`), all
  1018 rows.

### S3-03 `format(_:lang:)`
FORMATTING §5, one left-to-right pass over the pattern's `utf8` bytes (pattern letters and quotes
are ASCII; other bytes are copied through), writing through `appendFormat(_:to:)`; standard patterns `""`, `G`,
`g`, `d`, `D`, `s` (D-15).
- AC1: golden `format-pattern.tsv` (451 rows). Skip only rows whose pattern contains a run of exactly
  three `M` (today only `MMM yyyy`) and whose month is 3 or 6, with a `// D-04` comment. The test
  asserts it skipped at least one row and checked all the others.
- AC2: the six FORMATTING §5 examples, and `format("yyyy-MM-dd", lang: .nepali) == "२०८१-०४-१५"`
  for 2081-04-15.

### S3-04 Strict parse: `parse(_:)`, `init?(_:)`
PARSING §1 over the input's `utf8` view (ADR-0002 §5): ASCII digits, Devanagari digits
`E0 A5 A6` to `E0 A5 AF`, separators including `।` (`E0 A5 A4`) and `|`. Tokens are index ranges,
never `Substring` or `Array` values; errors are `throws(NepDateError)`. At most 4 digits per group (D-05). `init?(_:)` is `try? parse(_:)`.
- AC: every row of `shared/spec/vectors/parse.tsv` (57 rows), column `strict`: a date, or
  `ERR:<Kind>` mapped to `NepDateError.Kind` (`InvalidDay` matches `.invalidDay` with any
  `monthLength`).

### S3-05 `parseLenient(_:)`
PARSING §2 and the closed month list in §3, generated by `codegen` as UTF-8 byte sequences
inside a `switch` or as `StaticString`s compared byte by byte (no `[String]` table). Latin tokens
compare case-insensitively by lowercasing ASCII bytes only. Devanagari tokens compare as bytes;
`codegen` exits 1 if any month name differs from its own NFC or NFD form, so byte equality equals
canonical equivalence for the closed list (ADR-0002 §5). An input in NFD therefore fails to match:
add a `parse.tsv`-style test row that shows it, and list it in the PR for the human.
- AC1: every row of `parse.tsv`, column `lenient`.
- AC2: `parseLenient("15 Shrawan 2080")`, `parseLenient("Shrawan 15, 2080")` and
  `parseLenient("2080 Shrawan 15")` are all 2080-04-15; `parseLenient("15/04/80")` throws
  `.ambiguous`.

### S3-06 `Codable`, `LosslessStringConvertible`
D-11: encode as a single string `"YYYY-MM-DD"` (`format("s")`); decode with `parse(_:)` and turn a
`NepDateError` into `DecodingError.dataCorrupted`.
- AC1: `JSONEncoder` of `[d]` for 2081-04-15 gives `["2081-04-15"]`; decoding it gives `d`.
- AC2: decoding `"2081-04-33"` throws `DecodingError.dataCorrupted`.
- AC3: `NepaliDate(d.description) == d` for every date in golden `dates.tsv`.

### S3-07 Property test
A seeded generator (fixed seed, 100,000 strings of length 0...24 drawn from ASCII, Devanagari
digits, separators, `।`, month names and random scalars) feeds `parse` and `parseLenient`.
- AC: no crash; every thrown error is a `NepDateError`; every successful strict parse satisfies
  `try parse(d.format("s")) == d`.
