# ADR-0001: Package layout, toolchain and shared data

- Status: Accepted
- Date: 2026-10-06
- Deciders: Sanam Pakuwal

## Context

The Swift port is a spoke of the NepDate family (hub ADR-0001) and the calendar engine for the iOS
app and its widget extension (`nepdate-mobile` ADR-0003). The Swift Package Index has no Nepali date
package; the only maintained alternative ships a Kotlin/Native binary of about 7.7 MB per slice
(`docs/competitors.md`).

## Decision

1. **SwiftPM only**, no CocoaPods. `// swift-tools-version: 6.0`, `swiftLanguageModes: [.v6]`.
   Products `NepDate` (core) and `NepDatePatro` (the patro, पात्रो: tithi, public holidays, events),
   per hub ADR-0004. CocoaPods trunk goes read-only on 2026-12-02, so a new pod could not be
   published anyway (https://blog.cocoapods.org/CocoaPods-Specs-Repo/).
   `NepDatePatro` depends on `NepDate`; the `NepDate` target never depends on, imports or contains
   anything from `NepDatePatro`. The patro is a second product of this package, not a second package,
   because SwiftPM links only the products a target uses and one package keeps one tag.
2. **Platforms:** iOS 15, macOS 12, watchOS 8, tvOS 15, visionOS 1 (low minimums cost nothing for a
   pure-Swift library), plus Linux and Windows. CI builds on macOS, Linux and Windows (versions in
   ADR-0004); the Swift Package Index additionally
   builds Android and Wasm. The maintainer develops on Windows without a Mac (`nepdate-mobile`
   ADR-0010), so everything except the DocC preview must work there.
3. **No dependencies.** Dev tools, examples, benchmarks and fuzz targets are separate packages
   (`Tools/Codegen`, `Examples`, `Benchmarks`, `Fuzz`) with their own `Package.swift`, so users never
   resolve them.
4. **Foundation:** the core uses only the standard library. `Date`/`TimeZone` interop sits in one file
   behind `#if canImport(Foundation)`.
5. **Shared data:** `shared/` is a read-only copy of the hub's `data/` and `spec/` with
   `shared/VERSION`. CI calls the hub's reusable `shared-check`; the weekly `shared-sync` runs
   `swift run --package-path Tools/Codegen codegen`.
6. **Generator:** writes `Sources/NepDate/Calendar.generated.swift` and
   `Sources/NepDatePatro/Patro.generated.swift`, each starting with
   `// Generated by Tools/Codegen. DO NOT EDIT.` and `// swift-format-ignore-file`; `--check`
   fails on drift. The core generator reads only `shared/data/calendar/`; only the patro file
   reads `shared/data/patro/`.
7. **Docs:** DocC catalogue in `Sources/NepDate/NepDate.docc`, hosted by the Swift Package Index
   (`.spi.yml` with `documentation_targets: [NepDate, NepDatePatro]`).

## Consequences

- Adding the package to an app pulls in nothing else; the widget extension links only the code it
  uses. An app that only converts dates depends on `NepDate` and links no patro strings.
